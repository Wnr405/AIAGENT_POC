# ADR-0013: Zod 4 for request/env validation and OpenAPI generation

## Status

Accepted — 2026-11-28 (approved by the user during the `pnpm audit` remediation, branch `fix/deps-audit`)

## Context

The CI `security` job (`pnpm audit --audit-level high`, 05-METRICS §11.4) fails on a high advisory in zod 3.25.76
(memory exhaustion validating oversized constrained input). The only fixed versions are `zod >= 4.6.6`.
Critical/high findings cannot be waived (05-METRICS §15.3). Zod is the validation layer at every driving adapter
(04-ARCH §4.9), validates the environment at start-up (07-OPS-ARCH §7.3) and, through
`@asteasolutions/zod-to-openapi`, generates `openapi.json` (FR-PUBAPI-07, ADR-0008). zod-to-openapi 9 requires zod 4.

## Decision

Upgrade to `zod ^4.6.7` and `@asteasolutions/zod-to-openapi ^9.1.0`, keeping ADR-0008 unchanged. Migration rules:

- Defaults on schemas that **transform** (`bool`, `csv`, `duration` in `env.schema.ts`) use `.prefault()`: in zod 4
  `.default()` short-circuits and would return the raw string instead of the transformed value.
- String formats use the zod 4 top-level forms (`z.uuid()`, `z.url()`, `z.iso.datetime()`); `z.record` takes a
  key schema; `z.ZodType` replaces `z.ZodTypeAny`; custom issues use `code: 'custom'`.
- 422 field messages stay stable: `parse()` (`shared/http/validation.ts`) passes an error map that keeps the zod 3
  wording for missing / wrong-type fields ("Required", "Expected number, received string"), because cms-web shows
  these messages on form fields (04-ARCH §6.4). Messages a schema sets itself still win.

## Consequences

- `openapi.json` is byte-identical before and after (`pnpm openapi:check`, `openapi.spec.ts`).
- `z.uuid()` is RFC 9562-strict (version/variant nibbles): a malformed id in a path/query now gets 422 where a
  non-RFC hex string used to reach the use case and 404. Ids we issue (`randomUUID`) are unaffected.
- Other zod default messages (e.g. `too_small`) use zod 4 wording; only the two cases above are pinned.

## Alternatives Considered

- `zod/v3` compat import from the zod 4 package: clears the audit match without removing the vulnerable code path,
  and zod-to-openapi 9 does not accept v3 schemas.
- Waiver: not allowed for high findings (05-METRICS §15.3).
